# Home Office — Implementation Plan

**Status:** plan confirmed by the owner on 2026-09-06 ("yes", plus D11–D14). **Phases 0–7 complete** (2026-09-06); Phase 9 (D23: floors per project, Andrew and Lola) is in progress, Phase 8 (hardening, observability, tests) follows. Companion docs: `ARCHITECTURE.md` (how), `STACK.md` (with what, verified versions), `CONVENTIONS.md` (rules). Agents working on this repo: read `AGENTS.md` first, then this file; append to § Log when you finish a task.

- **D15 (2026-09-06) Browser in the sandbox.** Agents do frontend work, so the single agent image carries headless Chromium (Alpine `chromium` 142), Node 22 + npm, Bun 1.4.2 (musl, hash-pinned) and two preinstalled, pinned MCP servers: `@playwright/mcp` 0.0.80 (drive pages, snapshots, screenshots) and `chrome-devtools-mcp` 1.8.0 (performance, network, console). Both drive the distribution's Chromium with `--no-sandbox` (the container is the sandbox) and isolated profiles; screenshots land in `/tmp/browser`. Enabled for work and review sessions (`config.browser.enabled`), never for triage. Owner chose one image over a per-project variant or a sidecar; container defaults rise to 3 GB RAM and 2048 pids.
- **D16 (2026-09-06) Desktop shell wiring.** `apps/desktop` is a Bun workspace member and a Hutch project (`packageManager: "bun"`, Electrobun 2.0.1; devkit projected into the git-ignored `.hutch/`). The Bun main process runs `@ho/daemon` in-process and the window loads the **same UI bundle the daemon serves** over `http://127.0.0.1:<port>/` (one code path for desktop and browser); the launch token reaches the webview through a `preload` statement that parks it in `sessionStorage` (never in a URL). If a `ho daemon` is already healthy the app attaches to it instead of starting its own; a pid lock in `HO_HOME/desktop.lock` keeps one desktop instance. Quit = veto `before-quit`, stop sessions and GC, then quit. Packaged builds carry `Resources/app/ho/` (UI bundle, sprites, image contexts with a **prebuilt ho-runner** and the role packs, Drizzle migrations), assembled by `bun run desktop:prepare`; the daemon takes `resourcesRoot` explicitly and skips compiling the runner when the sources are absent. Logs go to `HO_HOME/logs/desktop.log`; PATH is widened with the usual Homebrew/Docker locations because Finder-launched apps do not see them.
- **D17 (2026-09-06) Mail intake shape.** `IntakeConnector` is a host-side adapter (`@ho/intake-github` drives the owner's authenticated `gh`; no token enters a sandbox). Every project carries an `intake` policy (enabled, interval 30–3600 s, label filter, dry run, acknowledgement label and comments). A polled issue becomes a `MailItem` plus a task in one command: a **triage task for the boss in the Lobby** (the brief carries issue number, project, link, author, labels, body) or, without a boss, a work task in the project inbox. Dedupe is by project + connector + external id against the event log. The office animates it: the **postman** (a visitor actor from the Lobby's street door) drops the envelope in the mailbox, a courier (clerk, else an idle colleague, else the boss) carries it to the boss, and the triage session waits behind the same gate as handoffs (`office.mailDelivered`, 20 s cap, no wait without viewers). The source hears back three times at most: received (comment + label), delegated (one comment per child task), outcome (done/blocked/failed with branch, PR link and report). Rejected: a separate mail state machine (the task already has one) and polling inside sandboxes.
- **D18 (2026-09-06) Provider agnosticism shape.** A static **provider catalog** in `@ho/protocol` (`PROVIDERS`: Claude Code, OpenCode, Gemini CLI, Codex) declares protocol (`stream-json` | `acp`), auth kinds (`subscription` | `api-key` | `none`), suggested models (free-form allowed where the CLI accepts any id), effort support, the CLI's state directory (mounted from the per-task config volume so sessions can resume) and scratch dirs (tmpfs on the read-only rootfs). Agents gain `auth`; core validates provider/model/effort/auth combinations on create and update. One generic **ACP runtime** (`@ho/runtime-acp`, `@agentclientprotocol/sdk` 1.4.0) drives every ACP agent over the existing runner relay (stdio JSON-RPC lines over the runner WebSocket): `initialize` → optional `authenticate` → `session/new` (or `session/load` when the agent advertises it and a resume id exists) → one `session/prompt` per office session; `session/update` chunks become `text_delta`/`tool_call`/`tool_result`, permission requests are auto-allowed (the sandbox is the permission boundary) and surfaced as `permission_request`, the stop reason becomes the `result`. The HO MCP server and the browser MCP servers are passed in `session/new` (`http` and stdio entries), and the office's system prompt appendix is prepended to the first prompt because ACP has no system-prompt parameter. Presets: `opencode acp` (model and permissions through `OPENCODE_CONFIG_CONTENT`), `gemini --acp --model … --approval-mode yolo` (`GEMINI_API_KEY`), `codex-acp` (`OPENAI_API_KEY`, Codex's own default model). **Image variants** are build targets of one Dockerfile (`ho/agent-<provider>:dev`, base layers shared; `ho/agent:dev` stays the Claude Code variant) and only the variants the roster needs are built. **API-key mode** for Claude Code swaps `CLAUDE_CODE_OAUTH_TOKEN` for `ANTHROPIC_API_KEY` and adds `--max-budget-usd` from the agent's `budgets.maxUsdPerTask`. Secrets: `anthropic-api-key`, `openai-api-key`, `gemini-api-key` join the store; the key an agent needs follows its provider (for OpenCode, the model's `provider/` prefix). Rejected: per-CLI bespoke adapters (ACP covers all three), running the CLIs' browser logins in sandboxes (not headless), and a registry that discovers models at runtime (the CLIs expose none uniformly).
- **D19 (2026-09-06) One office, art by key.** The owner-approved office (`assets/reference/office-base-v1.png`, D3's floors-per-project superseded) is the single floor everybody works on; projects are Board columns. The Codex layout lab (`/office-lab`, its own server, calibration scripts and sample sprites) is retired: its plan geometry moved into `packages/sim/src/office-plan.ts` as pure data with seat groups (dev/qa/analyst/boss) and its drawing became the app's floor renderer (`packages/ui/src/office/plan-view.ts` + `stand-ins.ts`). Every plan object carries a sprite key; the renderer shows the delivered PNG when the manifest has it and a palette-true geometric stand-in otherwise, so sprites are wired by dropping files into `assets/src` (contract in `assets/README.md`). Sprite production is the owner's (Codex generates, this repo only consumes native PNGs); the `@8x` importer, placeholder generators and reference sheets are gone, the historical spikes S1–S5 too. Live tuning: `bun run ui:watch` + `ho daemon --ui`, the page reloads itself in development builds.
- **D20 (2026-09-06) Art density: 24 px per cell.** One constant, `CELL_PX` in `packages/sim/src/office-plan.ts`, sets the pixels per cell for every sprite, the renderer and `bun run assets:import`; characters are 2 × 2 cells (48 × 48), bubbles 1 × 1, the office 1920 × 1104. The approved reference is drawn at ≈21 px per cell and a laptop pane shows the office at ≈27 device px per cell, so 16 px art upscaled and blurred; in the resampled comparison 24 was close to the reference and near 1:1 on Retina at fit-to-width, 32 only marginally sharper for twice the texture memory. Owner's pick 2026-09-06; the 16 px placeholders are scaled by the renderer until real sets arrive.
- **D21 (2026-09-07) Character canvas 2 × 5 cells.** Measured on the reference, standing people are ≈5 cells tall and 1.7 wide (foosball, kitchen), seated ≈4 from chair base to head; the 2 × 2 canvas of D20 made everyone half-size and the office feel small. Frames are 48 × 120 px, feet on the bottom row; the renderer scales a set by width (the 32 px placeholders stay 48 × 48 until real sets arrive) and floats the bubble above the actual head. Furniture footprints were confirmed correct; the remaining “small” impression comes from flatter generated art, addressed with per-object cut-outs of the reference as prompt images (`assets/reference/crops/`).

- **D23 (2026-09-07) Floors per project, Andrew and Lola.** (The Log's “proportion audit (D22)” entries refer to the unlisted D22 of the art tuning; this decision is D23.) The owner's flow: the app opens on an empty screen with a single button until the first project exists; every project is a **floor** (the same approved plan, its own staff) with its own boss **Andrew**, created together with the project, and the receptionist **Lola**, a fixed office character without an LLM. The chat talks only to the floor's boss: a human message becomes a triage task that Lola carries to Andrew as an envelope; he plans and delegates by walking the envelope to a colleague (or to himself when the floor has no staff — a work task assigned to the boss), finished work walks back to him and he posts the status in chat (deterministic status messages from the daemon, no tokens). An agent belongs to exactly one floor (`projectId`); adding a project can import copies of characters from other floors. The Lobby project without a repository is gone; triage tasks live in their project and the triage session sees the repository read-only. The event log written before D23 is incompatible: the daemon archives such a `ho.db` to `ho.db.bak-<timestamp>` on start and begins a fresh log (owner's choice; the old log held test data). The UI stays English; the boss answers in the language he is written to. Rejected: one shared Andrew riding between floors (one triage queue, more choreography), Lola as an agent record (validation surface without benefit), an upcaster for the old events.

## 1. Vision (restated requirements)

A monorepo **local multi-agent harness**: a desktop app (macOS Apple Silicon first, unsigned download from GitHub Releases) shows a pixel-art office in the LimeZu _Modern Office_ style. Employees are AI agents (name, appearance, gender, model, effort, base prompt, specialisation). A boss agent receives work from a chat panel on the right (or, later, from a postman delivering GitHub issues to a mailbox) and delegates to workers; workers hand work to each other **visibly** (walk over, hand it off). Idle agents wander, drink coffee, use the toilet, smoke, relax, sleep; emotions show in bubbles. Each agent session runs in an isolated Alpine-based Docker container; containers, caches and volumes are cleaned up aggressively. Everything is provider-agnostic (Claude first via **subscription**, later API keys, other CLIs, local LLMs) and sandbox-agnostic (Docker now, GCP later) through shared interfaces. Multiple repositories are first-class (one floor per project). Runs headless as a CLI on a server too. TypeScript everywhere on Bun, strictest typing and linting, ultra-modern stack, token- and hardware-frugal, secure. No tests in this phase.

## 6. Risks

| Risk                                                                             | Likelihood | Impact | Mitigation                                                                                    |
| -------------------------------------------------------------------------------- | ---------- | ------ | --------------------------------------------------------------------------------------------- |
| Electrobun maturity (single maintainer, docs drift, Bun-runtime mode edge cases) | Medium     | High   | Spike S2 gates D1; daemon is shell-agnostic; Tauri fallback documented.                       |
| Subscription rate limits (5-hour + weekly windows) throttle a multi-agent office | High       | High   | Concurrency caps, Sonnet/Haiku for workers, RTK, lean context, rate-limit pause, usage panel. |
| Anthropic policy changes around headless/subscription use                        | Low–Medium | High   | Use only the official CLI and `setup-token`; API-key mode as fallback (Phase 7.4).            |
| TypeScript 7.0 tooling gaps (no compiler API; `tsc -b` behaviour)                | Medium     | Low    | Oxc toolchain only; verify in P0.1; TS 7.1 restores an API.                                   |
| Docker Desktop VM RAM (~8 GB) limits concurrent containers                       | Medium     | Medium | Memory limits per session, default concurrency 2, idle stop, doctor warnings.                 |
| RTK lossy compression hides a relevant error                                     | Low        | Medium | Exclude risky commands via `~/.config/rtk/config.toml`; agents can rerun without `rtk`.       |
| Prompt cache misses across resumed sessions inflate usage                        | Medium     | Medium | Keep sessions alive within 1 h, never mutate system prompt/tool set mid-session.              |
| Sprite production bottleneck                                                     | Medium     | Low    | Placeholder generated sprites in Phase 4; asset list published early (§5).                    |
| Disk growth from images/volumes/caches                                           | Medium     | Medium | Labels + GC job + retention policies + Resources panel; P8.5 audit.                           |
